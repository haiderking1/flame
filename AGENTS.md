# Agent Guidelines

**Before implementing:** Read this `AGENTS.md` and any applicable nested `AGENTS.md` files before making implementation changes, including when resuming after a user clarification or conversation compaction. Apply the instructions to the ongoing work; merely acknowledging or editing them is not a substitute for following them.

1. **No god files.** Keep implementations modular, with one clear responsibility per module. Split unrelated concerns into separate files. Group related responsibilities in nested directories, with each file retaining a single clear responsibility.
2. **Production-quality implementations only.** Never substitute simplified, toy, placeholder, or shortcut implementations for production-ready code. Include appropriate validation, error handling, and tests for the agreed scope.
3. **Work incrementally.** Let the user choose each step and approve technology and architecture decisions. Implement only the requested scope; do not scaffold or add features ahead of approval.
4. **Continue through obvious next steps.** Once the user has assigned a task, do not stop after a preparatory step or ask for permission to continue when the next step is clear and within the approved scope. A user clarification or correction updates the ongoing task; acknowledge it briefly and resume implementation in the same turn instead of ending with acknowledgment alone. Keep working until the task is complete or a genuine blocker or unapproved decision requires user input.
5. **Deliver requested features end to end.** Do not silently reduce a requested working feature to a core, foundation, standalone module, or partially integrated implementation. Internal implementation steps are not separate deliverables unless the user explicitly agrees. Complete the necessary backend, persistence, lifecycle and failure handling, model integration, and UI for the agreed feature before calling it done. Verify the integrated behavior, not just isolated helpers. If a genuine blocker prevents completion, state exactly what remains and why; do not present groundwork as fulfillment of the request.
